# Motors API

HTTP API для управления манипулятором и получения данных с сервоприводов.

- **Базовый префикс:** `/api/motors`
- **Формат данных:** `application/json`
- **Базовый URL (пример):** `http://127.0.0.1:8000`
- **Моторы:** 6 штук, идентификаторы `1`–`6`

# Запуск
- pip install -r requirements.txt
- uvicorn main:app

## Сводка эндпоинтов

| Метод | Путь | Название | Назначение |
| --- | --- | --- | --- |
| POST | `/api/motors/pos/set` | Set Pos | Задать целевую позицию руки и состояние схвата |
| GET | `/api/motors/pos` | Get Pos | Получить текущую позицию моторов |
| GET | `/api/motors/temp` | Get Temp | Получить температуру моторов |
| GET | `/api/motors/load` | Get Load | Получить нагрузку на моторы |
| WS | `/ws` | Exec | Отправить команду движения и получить подтверждение по завершении |

## Формат ответов GET-методов

Все три метода чтения (`pos`, `temp`, `load`) возвращают код `200` и **массив объектов**. В каждом объекте один ключ: id мотора (строка), значение: целое число.

```json
[
  { "1": <значение> },
  { "2": <значение> },
  { "3": <значение> },
  { "4": <значение> },
  { "5": <значение> },
  { "6": <значение> }
]
```

Объектов ровно по числу моторов, порядок соответствует id 1…6. Чтобы получить значение по id, массив нужно склеить в один словарь (пример в разделе про клиента).

## GET `/api/motors/pos`

Возвращает текущую позицию каждого мотора в «сырых» единицах сервопривода (тиках).

**Параметры и тело запроса:** нет.

```bash
curl -X 'GET' 'http://127.0.0.1:8000/api/motors/pos' -H 'accept: */*'
```

**Ответ `200`**

```json
[
  { "1": 2048 },
  { "2": 2051 },
  { "3": 2094 },
  { "4": 1003 },
  { "5": 512 },
  { "6": 710 }
]
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `"<id>"` | integer | Текущая позиция мотора `<id>` в тиках |

## POST `/api/motors/pos/set`

Задаёт новую позицию руки и состояние схвата.

**Параметры запроса (query/path):** нет.

**Тело запроса (обязательное):** `application/json`

| Поле | Тип | Описание |
| --- | --- | --- |
| `x` | number | Координата X целевой позиции |
| `z` | number | Координата Z целевой позиции |
| `angel` | number | Угол (имя поля в API написано именно так, с опечаткой) |
| `pov_gripper` | number | Поворот схвата (предположительно, по названию) |
| `gripper_state` | boolean | Состояние схвата: `true` / `false` (какое значение открыто, а какое закрыто, уточнить) |

Обязательность отдельных полей, диапазоны и точные типы (integer или number) на скриншоте не видны, смотрите вкладку *Schema* в Swagger.

**Пример тела запроса**

```json
{
  "x": 0,
  "z": 0,
  "angel": 0,
  "pov_gripper": 0,
  "gripper_state": true
}
```

**Пример вызова**

```bash
curl -X POST http://127.0.0.1:8000/api/motors/pos/set \
  -H "Content-Type: application/json" \
  -d '{"x": 0, "z": 0, "angel": 0, "pov_gripper": 0, "gripper_state": true}'
```

**Ответ:** уточнить (успешный ответ и коды ошибок на скриншоте не показаны).

## WebSocket `/ws`

Двусторонний канал для команд движения. Клиент отправляет команду, а сервер присылает сообщение **после завершения движения**.

- **URL:** `ws://127.0.0.1:8000/ws`
- **Формат сообщений:** JSON (текстовые фреймы)

### Сообщение клиента: команда движения

| Поле | Тип | Описание |
| --- | --- | --- |
| `command` | string | Тип команды. В примере `"exec"` (выполнить движение); другие значения, если есть, уточнить |
| `x` | number | Координата X целевой позиции |
| `z` | number | Координата Z целевой позиции |
| `angel` | number | Угол (имя поля с опечаткой, как и в HTTP) |
| `pov_gripper` | number | Поворот схвата (предположительно, по названию) |
| `gripper_state` | boolean | Состояние схвата |

Поля `x`, `z`, `angel`, `pov_gripper`, `gripper_state` совпадают с телом `POST /api/motors/pos/set`. Добавляется только поле `command`.

```json
{
  "command": "exec",
  "x": 250,
  "z": 150,
  "angel": 180,
  "pov_gripper": 10,
  "gripper_state": false
}
```

### Сообщение сервера: успех

Отправляется, когда движение выполнено.

```json
{
  "status": "ok",
  "message": "move completed"
}
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `status` | string | `"ok"` при успешном выполнении |
| `message` | string | Текст результата, `"move completed"` |

В отправленном примере ответ пришёл примерно через 130 мс после команды. Реальное время зависит от длины движения.

### Сообщение сервера: ошибка

Формат сообщения об ошибке на скриншоте не показан, уточнить.

### Пример сессии

```
клиент  -> {"command": "exec", "x": 250, "z": 150, "angel": 180, "pov_gripper": 10, "gripper_state": false}
сервер  -> {"status": "ok", "message": "move completed"}
```

## Пример клиента на Python

```python
import requests

BASE = "http://127.0.0.1:8000/api/motors"


def as_dict(items: list[dict]) -> dict[int, int]:
    """[{"1": 35}, {"2": 42}] -> {1: 35, 2: 42}"""
    return {int(k): v for item in items for k, v in item.items()}


# Задать позицию
r = requests.post(f"{BASE}/pos/set", json={
    "x": 0, "z": 0, "angel": 0, "pov_gripper": 0, "gripper_state": True,
})
print(r.status_code, r.text)

# Прочитать данные
pos = as_dict(requests.get(f"{BASE}/pos").json())    # {1: 2048, 2: 2051, ...}
temp = as_dict(requests.get(f"{BASE}/temp").json())  # {1: 35, 2: 42, ...}
load = as_dict(requests.get(f"{BASE}/load").json())  # {1: 8, 2: 1096, ...}
print(pos, temp, load)
```

WebSocket-клиент (`pip install websockets`):

```python
import asyncio
import json

import websockets


async def main():
    async with websockets.connect("ws://127.0.0.1:8000/ws") as ws:
        await ws.send(json.dumps({
            "command": "exec",
            "x": 250, "z": 150, "angel": 180,
            "pov_gripper": 10, "gripper_state": False,
        }))
        reply = json.loads(await ws.recv())  # придёт после завершения движения
        print(reply)  # {"status": "ok", "message": "move completed"}


asyncio.run(main())
```

## Наблюдения по данным

- Позиции моторов 1–4 лежат в диапазоне до 4095 (шкала XL/XM, 2048 ≈ середина), а у моторов 5 и 6 значения 512 и 710, что похоже на шкалу 0–1023. Возможно, в руке стоят серво разных серий. Стоит проверить перед пересчётом градусов в тики.
- В нагрузке у моторов 2, 3, 4 и 6 значения больше 1023. Если это серии с протоколом AX, старший бит может кодировать направление нагрузки. Единицы измерения нужно уточнить.
